## Tasks

- [x] 1.1 Added `intl` to `pubspec.yaml` (was already a transitive dependency; made direct since `lib/` code now imports it).
- [x] 1.2 `formatAmountMinor` now requires a `currency` parameter and uses `NumberFormat.currency(locale: ..., name: currency, symbol: '')`. Required adding a small `currency -> locale` map beyond what design.md originally anticipated - see design.md's "Correction, found during implementation" note (grouping/decimal-separator conventions are locale-sourced in `intl`, not currency-sourced; only minor-unit digit count is truly per-currency).
- [x] 1.3 `MoneyAmountField` now requires a `currency` parameter, is a `StatefulWidget` with an explicit `errorText: 'Enter a valid amount'` state for non-empty unparseable input (empty stays neutral, matching "not entered yet"). New `parseAmountToMinor` in `money_formatter.dart` normalizes the currency's own grouping/decimal separators before parsing.
- [x] 1.4 Swept every `formatAmountMinor`/`MoneyAmountField` call site (Home, Register - added `RegisterRow.currency` - Summary, Settle pending transfer, Statement import preview, Migration review, Account management, Correction wizard - added `CorrectionViewModel.currency` - Record transaction, Transfer). Fixed the transfer implied-rate comment/computation (`transfer_view_model.dart`): the old code divided raw minor units directly, silently correct only because every currency was assumed two-decimal before this change - now converts each side to its own major units first via a new `minorUnitDigitsForCurrency` helper, fixing a real (if previously undetectable) bug for any currency pair with different minor-unit digit counts (e.g. USD/JPY).
- [x] 1.5 Tests: `money_formatter_test.dart` (INR/JPY/EUR/USD formatting matches `intl`'s own data, negative sign, unmapped-currency fallback, no cross-call locale leakage; comma/period parsing per currency, grouping-separator stripping, empty vs. unparseable), `money_amount_field_test.dart` (explicit error state, EUR comma acceptance, USD grouping-separator handling), plus a `transfer_view_model_test.dart` regression test locking in the USD/JPY implied-rate fix. Existing widget tests asserting the old ungrouped "1234.56"-style text were updated to the new grouped format.
- [x] 1.6 User guide: added a paragraph after the accounts/groups section explaining amounts format and parse per their own currency's convention, with concrete INR/JPY/EUR examples.

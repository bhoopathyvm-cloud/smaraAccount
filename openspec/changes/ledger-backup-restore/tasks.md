## Tasks

- [x] 1.1 `LedgerRepository.exportLedgerBackup`: checkpoints the WAL, reads the raw database file, encrypts it under a user-supplied passphrase via a new `LedgerBackupFile` primitive (same AES-256-GCM/PBKDF2 family as `KeystoreFile`, kept as its own class since it protects a much larger, structurally different payload). Never includes private key material - the encrypted bytes are the database file only.
- [x] 1.2 Confirmed: the raw database file backup already includes `signing_identities` (it's the whole database file, not a table-by-table export), and a dedicated test (`exportLedgerBackup never includes the private key material`) checks the encrypted envelope carries no key-shaped fields.
- [x] 1.3 `LedgerRepository.restoreLedgerBackup`: decrypts with the supplied passphrase, opens the decrypted bytes as a real `AppDatabase` (new `AppDatabase.openFile` constructor) to validate it's a genuine ledger with an active identity, runs `verifyChain()` and rejects a backup that is not fully verified, rejects a foreign identity, then closes this repository's connection and replaces the real database file. UI (`SettingsView`) shows the replace-what confirmation via `confirmDestructiveAction` before calling this.
- [x] 1.4 Verified by the round-trip test: `verifyChain()` on a freshly reopened connection to the restored file reports `isFullyVerified: true` using only what's in the backup.
- [x] 1.5 Settings UI: Save backup / Restore backup actions, passphrase prompts (Save), file-picker + passphrase (Restore), `confirmDestructiveAction`-based replace confirmation, and a post-restore "close the app to continue" screen (this repository's DI wires `AppDatabase` once at startup - a live in-place hot-swap isn't attempted; the app must restart to open a fresh connection to the replaced file, which the design.md decisions didn't call out explicitly but follows directly from "replace is the only mode").
- [x] 1.6 Tests (`test/data/repositories/ledger_backup_restore_test.dart`, real file-backed databases, not in-memory): export/restore round-trip reproduces identical ledger state and is fully verified; restore rejected when identities mismatch, target file untouched; restore onto a fresh device succeeds and is read/verify-only (`recordTransaction` throws `StateError` - no matching key in secure storage) until the key is separately restored; wrong passphrase fails cleanly with no partial replacement.

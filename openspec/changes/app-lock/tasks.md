## Tasks

- [x] 1.1 Lock gate in `app_router.dart`: new `AppLockController` (`lib/ui/core/app_lock_controller.dart`, a `ChangeNotifier` + `WidgetsBindingObserver`) tracks unlocked-this-session state and passed as `GoRouter`'s `refreshListenable` so a relock takes effect immediately. Redirect checks `settingsRepository.isAppLockEnabled()` + `appLockController.isUnlocked` once the ledger itself is reachable (after onboarding/restore/currency-backfill, which show no financial content to protect). Cold start always begins locked.
- [x] 1.2 PIN set/change flow (`AppLockService`, `lib/domain/lock/`: salted PBKDF2 hash in secure storage, same primitive family as recovery-phrase/keystore crypto) and `local_auth` biometric option (`BiometricAuthenticator` interface + `LocalAuthBiometricAuthenticator`, offered only where `isDeviceSupported()` is true). Native config added: iOS/macOS `NSFaceIDUsageDescription`, Android `FlutterFragmentActivity` + `USE_BIOMETRIC` permission - not device-tested in this environment (no attached device/simulator), so treat the biometric path as implemented-but-unverified-on-real-hardware.
- [x] 1.3 Settings: enable lock (prompts to set a PIN), change PIN, timeout dropdown (Immediately/1/5/15 minutes), biometric toggle (shown only when available).
- [x] 1.4 Snapshot hiding: implemented as a pure-Flutter `WidgetsBindingObserver` overlay (`SnapshotHidingOverlay`, wraps the whole app above `MaterialApp.router`) that covers the screen synchronously the instant lifecycle state becomes inactive/paused/hidden - the "overlay shown while backgrounded" option design.md named, not a native secure-flag plugin. Works on iOS and Android (the two platforms `SettingsViewModel.isSnapshotHidingAvailable` reports true for); Settings states plainly on macOS/Windows that there's nothing to turn on. **Correction, found during implementation (see design.md):** wrapping above `MaterialApp.router` meant the overlay's own `Stack`/`Icon` had no `Directionality` ancestor and crashed the instant the cover rendered - only reproduced running the real app, not caught by the original widget test's `MaterialApp`-wrapped setup. Fixed with an explicit `Directionality(textDirection: TextDirection.ltr, ...)` inside `SnapshotHidingOverlay` itself; regression test added that omits any `Directionality` ancestor.
- [x] 1.5 Tests: `AppLockService` (PIN hash/verify/clear, salted so repeat PINs produce different records), `LockViewModel` (PIN submit success/failure, biometric auto-prompt-on-open gated by the setting, a cancelled biometric prompt leaves the PIN field usable with no error), `AppLockController` (cold-start-locked, markUnlocked, backgrounded tracking, relock-on-resume gated by enabled+timeout, synchronous snapshot-hiding cache), `SnapshotHidingOverlay` (covers only when backgrounded AND enabled), and `SettingsView` (set-PIN dialog flow, mismatched-PIN block, disable-clears-PIN, timeout/Change-PIN only shown once enabled).
- [x] 1.6 User guide Settings section: enabling lock and the PIN dialog, Change PIN, the timeout choices, the biometric toggle's availability condition, and snapshot hiding's iOS/Android-only coverage.

# Apple builds use only the operating system's cryptography

App Store Connect asks whether the app contains encryption beyond what Apple's operating system provides. Until this decision it did: AES-256-GCM, PBKDF2, Ed25519, HMAC and SHA-256 came from the pure-Dart `cryptography` package, linked-device TLS from Dart's BoringSSL, the device TLS identity from `basic_utils`, and HTTPS lookups from Dart's HTTP client. Once Books Copy files and device sync were encrypted (2026.10.0), the declaration `ITSAppUsesNonExemptEncryption = false` no longer matched Apple's definition, and the owner does not want the app in the category that brings export documentation and reporting duties. We decided that on iOS and macOS every cryptographic operation goes through Apple's frameworks, and that Android, Windows and Linux keep their Dart implementations, with cross-platform operation as the primary constraint.

The code enforces it through one seam. `CryptoBackend` (`lib/domain/crypto/`) is the only way the app encrypts, derives keys, signs, verifies, authenticates or hashes; `DartCryptoBackend` is the only file under `lib/` that imports a Dart crypto library, and `AppleCryptoBackend` calls CryptoKit and CommonCrypto through the in-repo `smara_apple_crypto` plugin (`packages/smara_apple_crypto`). The backend is chosen once at startup from the platform; in debug and test builds the Dart backend throws if it is ever reached on iOS or macOS, so an Apple build can never fall back silently. The same shape covers TLS (`TlsSocketFactory`: `dart:io` sockets or the Network framework, with the length-prefixed JSON framing and the fingerprint pinning staying in Dart), the device identity (`AppleDeviceCertificateStore`: an RSA-2048 key created and kept in the Keychain by the Security framework, which signs the X.509 structure Dart assembles) and HTTPS (`cupertino_http`'s URLSession client). Golden vectors from the RFCs and NIST run against both backends, and a cross-platform matrix (Apple with Android, both directions, for join, sync, scoped sync, unknown-peer refusal and Books Copy restore) is the release gate.

The trade-offs we accepted: a second implementation of every format, kept honest by the shared golden suite; new, security-relevant Swift code, kept small and unit-tested on simulators and devices; a platform-channel round trip per operation, with hashing batched for chain verification; and Ed25519 signatures that are no longer byte-identical across platforms (CryptoKit hedges them), so nothing may compare signature bytes, only verify them. The Flutter engine still links BoringSSL for `dart:io`, which the Apple builds no longer call; whether an unused copy matters is a judgement the owner confirms before each submission that declares `false`. This decision does not change file formats, the sync wire protocol or the pinning model, and it is not legal advice.

## Considered Options

- **`cryptography_flutter`, which routes `package:cryptography` to CryptoKit** — rejected: it falls back to its pure-Dart code for any algorithm or parameter set it does not accelerate, silently, and the fallback cannot be ruled out by a test.
- **URLSession WebSockets for device sync** — rejected: it changes the wire protocol and breaks peers on Android, Windows and Linux.
- **P-256 (Secure Enclave) device keys on iPhone** — deferred: RSA-2048 keeps one certificate type on every platform and leaves the other platforms untouched. Revisit separately if Secure Enclave keys are wanted.
- **Declare the app non-exempt and file the export paperwork** — rejected by the owner.

## Consequences

Any new cryptographic use goes through `CryptoBackend` (and any new socket through `TlsSocketFactory`); a `lib/` import of a crypto library anywhere else fails `crypto_backend_selection_test.dart`. `test/platform/export_compliance_test.dart` keeps both Info.plist files at `false` and the privacy policy's export-compliance section stating the operating-system-only basis. Changing this decision reopens the export-compliance question, the privacy policy and ADR 0004's "private key never leaves the device" (the Apple TLS private key now lives in the Keychain and never reaches Dart at all).

Established with the OpenSpec change `os-provided-encryption`.
